# 排课选课与教务协作智能体系统 · 一页纸需求清单

- 版本：v0.1 草稿（待《需求评审 10 问》确认后定稿）· 2026-10-30
- 依据：discovery-report.md（知行职业学院，36/36 事实采集）+ 报告默认假设
- 状态：候选需求，均为待验证假设，不等于验收通过

## 1. 背景与业务目标
| 项 | 内容 |
|---|---|
| 核心痛点 | 学生选中课后才发现先修课/教室冲突；关键说明留在个人便签，交接无凭证 |
| 现状基线 | 每学期 420 门次课程；开学周日均 120 个调整请求；调课处理约 3 天 |
| 业务目标 | 选课冲突 360 → 80 /学期；调课处理 3 天 → 1 天 |
| 试点验收 | 一个专业试点；时空冲突识别率 100%；人工调整工时降 30%（口径待 Q9） |

## 2. 用户与角色（MVP 三角色 → 实际岗位映射）
| 系统角色 | 对应岗位 | 核心功能 |
|---|---|---|
| 学生 | 学生 | 制度问答（RAG）、查课表、选课前冲突预检、选课申请草稿 |
| 教师 | 专业课程负责人/任课教师 | 查课表、提交调课申请 |
| 教务管理员 | 排课专员/教务主任/教学质量专员 | 知识库与版本管理、提示词模板、对话审计、人工修复与转人工队列 |

## 3. 范围内 · P0
1. **制度知识库 RAG 问答**：排课规则、选课规则、学分与课表标准；回答必须附引用来源（文件名+片段）；未命中明确答"制度中未找到"，不得编造。
2. **选课前冲突预检**（REQ-1）：先修课冲突 + 教室时空冲突；**确定性规则引擎判定，LLM 仅负责解释**；提示必须显示对应原记录与待确认字段。
3. **选课申请草稿流程**：资格校验（validate_eligibility）→ 学生流式确认 → 生成申请单（草稿态）→ 教务人工确认后由人在教务系统执行（系统接口只读，不代选课）。
4. **审计留痕**（REQ-4 / f45）：业务编号、资料版本、事实引用、工具调用轨迹、人工改动、签核人；评价记录暂保留 90 天（暂定，f43）。

## 4. 范围内 · P1
- 教师调课申请提交与状态跟踪
- 场地维护占用状态纳入冲突校验 + 异常暂停建议、排课专员核对后继续（REQ-3）
- 数据状态展示：每 15 分钟更新，超周期标"待刷新"；接口中断用带时间戳只读快照 + "暂未更新"（REQ-5）
- 对话审计页：按角色/时间筛选、疑似违规标记（如试图绕过选课资格）

## 5. 范围外（硬边界）
- ❌ 不自动改变培养计划（f05/f52）
- ❌ 不自动替学生选课、不修改成绩（接口只读，f32）
- ❌ 歧义记录（课程新旧代码/跨学院规则冲突）不进自动推荐，进人工修复队列（f33）
- ❌ 试点不铺年级、不跨院系；LLM 不做冲突判定与资格终审

## 6. 关键非功能约束
- **数据**：教务系统/场地预约/学籍库三系统只读对接，账号权限独立维护。
- **转人工触发**（f44）：资料缺依据 / 规则版本冲突 / 关键系统不可用 / 场地维护异常；须标注触发原因、接手人、确认时间。
- **隐私**：学生数据脱敏后才可出校调用 LLM（Q6 确认）；不记录账号口令与不必要个人信息。
- **兜底**：LLM 超时/工具失败 → 返回明确中文错误码与"转人工"出口，不静默失败。

## 8. 里程碑（阶段 1–5）
| 阶段 | 内容 | 验证物 |
|---|---|---|
| 1 | 裸问答原型：RAG（500 字切片）+ BM25/向量混合检索 top3 + LLM 供应商可配置 | 命令行跑通 3 个制度问题（含 1 个"未找到"） |
| 2 | 学生端：POST /chat SSE 流式 + 会话/消息落库 + 最近 6 轮上下文 + 引用展示 | 浏览器端演示 |
| 3 | 管理后台：JWT 三角色、知识库上传/切片/向量化/删除、提示词模板热更新、审计页 | 管理员可运营 |
| 4 | Agent 化：工具（查课表/查规则/校验资格/建申请）+ 编排循环 ≤5 轮 + 决策日志 + 申请前强制学生确认 | 3 条典型轨迹全部通过 |
| 5 | 评测（30 用例：制度 10/工具 10/违规 5/多轮 5）+ 上线检查清单 | 评测报告 + 检查单签核 |
