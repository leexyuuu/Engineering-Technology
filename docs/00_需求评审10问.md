## Q1 课程主数据与主编号（阻塞 P0）
- 问：课程新旧代码并存，试点以哪套代码为主编号？跨学院学生权限与容量规则以谁为准？
- 架构差异：统一主数据视图 → 需要数据集成层（字段映射 + 版本字段 + 歧义人工修复队列），检索与冲突引擎都基于规范化课程实体；以教务系统单源为准 → 轻量只读适配器直连，开发快，但跨学院资格判断不可靠，"识别率 100%"的验收无法成立。

## Q2 冲突预检的类型与判定方式
- 问：第一期冲突预检覆盖哪些类型——先修课冲突、教室时空冲突、教师排班冲突、场地维护占用？判定用确定性规则引擎还是 LLM？
- 架构差异：确定性规则引擎（可解释、可审计，识别率可验收）→ 冲突引擎独立成模块，Agent 以工具方式调用；LLM 判定 → 不可审计、无法承诺 100% 识别率，不建议。场地维护数据若纳入 → 需新增场地预约系统数据源与状态同步，复杂度上升。
- 报告默认：P0 = 先修课 + 教室时空冲突（规则引擎）；场地维护占用 P1（f11/f15）；教师排班冲突暂不做。

## Q3 选课/调课申请的确认链路（阻塞 P0）
- 问：系统生成的选课申请，确认链路是"学生确认 → 教务确认 → 人工在教务系统执行"吗？特殊申请终审人是谁？教师调课申请是否同链路？
- 架构差异：需要申请单状态机（草稿 → 学生已确认 → 教务已确认 → 已执行/已驳回）+ 待办通知 → 新增审批模块与申请单表；若仅生成建议文本 → 无状态机，但与"特殊申请由教务确认"（f40）的验收要求冲突。
- 报告默认：接口只读、不能替学生选课（f32）；特殊申请由教务确认（f40）；系统只做冲突检查与方案建议，不自动改变培养计划（f05/f52）。

## Q4 制度知识库范围与版本管理
- 问：知识库首期收录哪些制度文档（排课规则/选课规则/学分与课表标准/调课管理办法）？规则版本冲突时系统如何呈现？
- 架构差异：文档实体带生效日期/适用范围/版本号 → RAG 检索需版本过滤 + 冲突标记（冲突时同时返回两个版本、不自动合并、转教学质量专员）；无版本管理 → 检索可能返回过期规则，审计无法对齐"资料版本"字段。
- 报告默认：规则由业务负责人维护，按生效日期和适用范围选版本；冲突附双版本给教学质量专员，不自行合并、不挑宽松条款（f24）。

## Q5 角色与权限粒度
- 问：MVP 用三角色（学生/教师/教务管理员），还是细分六岗位（辅导员/排课专员/系统工程师/质量专员/课程负责人/教务主任）？权限到接口级还是再加数据级（本人数据/跨学院）？
- 架构差异：三角色 → JWT 单角色 claim + 接口级依赖校验，简单；细分岗位 → 需要岗位-权限矩阵配置页 + 数据级过滤，管理端复杂度上升，审计页筛选维度随之变化。
- 报告默认：MVP 三角色；管理端内部再分"知识库维护 / 审计只读 / 申请终审"三类操作权限；学生仅能查本人课表与申请。

## Q6 部署方案与 LLM 数据出校合规（阻塞 P0）
- 问：部署在校内私有化还是公有云？LLM 用外部 API（供应商可替换）还是本地化模型？学生姓名/学号等能否出校？
- 架构差异：外部 API → 必须加脱敏代理层（出校前把学号/姓名替换为占位符，回填在本地完成）+ 供应商可配置抽象；本地化模型 → GPU 资源与运维成本，但合规最简。此答案决定第 1 周 MVP 的 LLM 封装是否要先做脱敏管道。
- 报告默认：LLM 供应商可配置（技术约束）；学生隐私脱敏后才出校；部署形态待定（首期预算 10 万内，f03）。

## Q7 并发规模与 LLM 配额
- 问：选课高峰的并发预估是多少（开学周日均 120 个调整请求的峰值放大倍数）？LLM 月度调用配额/预算多少？
- 架构差异：小规模（<100 并发 SSE）→ SQLite + 单实例 FastAPI 足够；更高 → PostgreSQL + 连接池 + 令牌桶限流 + LLM 配额熔断（超配额时降级为"仅规则提示、不生成解释"）。
- 报告默认：按日均 120 请求 × 开学周峰值 5–10 倍估算；首期 SQLite 起步，保留切换 PostgreSQL 的 ORM 抽象。

## Q8 "待刷新"与接口中断是否阻断操作
- 问：数据超过 15 分钟更新周期标"待刷新"时，选课申请是仅提示还是阻断？接口中断重连补齐失败由谁核对、告警接收人是谁？
- 架构差异：仅提示 → 缓存层带时间戳快照 + 状态标记（fresh/stale），Agent 工具照常执行但结果带"待刷新"标注；阻断 → 冲突预检/建申请工具前置校验数据新鲜度，stale 时直接拒绝并转人工。两者失败路径与用户文案完全不同。
- 报告默认：待刷新仅提示、不阻断、不作实时承诺（f34）；中断用带时间戳只读快照 + "暂未更新"标识，人工流程继续（f35）；阻断策略待秦芮/林亦舟确认。
- 你的回答：＿＿＿
