# 问答助手归档

> 交付项：src-1 ｜ 归档对象：面向学生 / 教师 / 教务管理员的**制度问答助手**（RAG + Agent 工具调用 + SSE 流式）
> 归档日期：2026-11-06 ｜ 系统版本：`app.main:app` v0.4.0 ｜ 代码基线：仓库 `master` 分支

## 1. 归档目的与边界

- **目的**：把问答助手的「可运行代码 + 可追溯数据 + 可复现评测 + 可运营后台」四类资产登记在一处，
  供评审、交接与复测；后续迭代只需按本索引追踪变更。
- **边界**：本目录**不复制代码**。代码唯一副本在仓库 `app/` 下，本文只给路径与职责；
  避免双副本导致版本漂移（历史教训：手工复制代码后出现两套不一致实现）。
- **归档判定**：以下四类资产全部齐备，即可认为问答助手已归档。

| 资产类别 | 是否齐备 | 位置 |
| --- | --- | --- |
| 可运行代码 | 是 | `app/`（入口 `app/main.py`） |
| 知识库与数据 | 是 | `data/docs/教务管理制度.md`、`data/faiss/`、`data/app.db`（运行数据不入库） |
| 评测与回归 | 是 | `eval/eval_cases.json`（30 例）、`scripts/stage3_test.py` 等 4 个脚本 |
| 运营后台 | 是 | `/admin/kb`、`/admin/prompt`、`/admin/audit`、`/admin/applications` |
| 文档与配置 | 是 | `README.md`、`.env.example`、`docs/`、`src/` |

## 3. 问答助手运行入口

```powershell
# 1) 安装依赖（首次）
.venv\Scripts\python.exe -m pip install -r requirements.txt

# 2) 启动（默认 mock 供应商，离线可用）
.venv\Scripts\python.exe -m uvicorn app.main:app --port 8000

# 3) 访问
#    学生聊天页  http://127.0.0.1:8000/login
#    管理后台    http://127.0.0.1:8000/admin/kb
#    演示账号    student1 / teacher1 / admin1，密码 123456
```

首次启动自动完成：建表 → 写入 3 个演示账号 → 初始化提示词模板 → `data/docs/` 制度入库 → 构建 FAISS 索引。

## 4. 问答链路（一次请求发生了什么）

```text
用户提问
  → ① 鉴权（JWT）→ ② 限流（20 次/分钟/IP）→ ③ 会话校验（不存在返回 40401）
  → ④ 背景混合检索：FAISS 向量 + BM25 词法 → RRF 融合取 top3
  → ⑤ 装载最近 6 轮历史 + 当前生效的提示词模板
  → ⑥ Agent 循环（≤5 轮）：
        ├─ 工具调用：查课表 / 检索制度 / 查课程要求 / 校验资格 / 建选课申请
        ├─ 直答：流式输出最终回答
        └─ 建申请成功 → 发确认卡片并中断（等学生本人确认）
  → ⑦ SSE 事件：status → tool(×N) → [confirm_required] → message(×N) → citations → done
  → ⑧ 落库：用户消息、助手回答、引用来源、每轮决策日志
```

异常路径：检索失败 → `50001`；供应商失败/超时 → `50301/50302`；工具异常 → 结构化说明（不中断对话）；
超过 5 轮 → 自动退回 RAG 直答；任何错误都以 `{code, message}` 中文结构返回，不返回堆栈。

## 5. 归档规则（后续维护约定）

1. **代码不复制**：新增能力直接改 `app/`，本目录只更新路径与职责说明。
2. **数据不入库**：`data/app.db`、`data/faiss/`、`data/uploads/`、备份与日志均被 `.gitignore` 排除。
3. **配置不入库**：`.env`（含密钥）永不提交；只提交 `.env.example`。
4. **评测随代码走**：行为变更必须同步更新 `eval/eval_cases.json` 与对应断言，并在发布记录中写明基线变化。
5. **发布可回滚**：每次上线打 Git tag，回滚按 `docs/02_上线检查清单.md` RB-1 执行。
